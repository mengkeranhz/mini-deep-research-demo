# 通用行程规划

本技能只换研究对象与产物形态，不豁免也不替代宿主的研究纪律：locate_sources 定权威域名、web_search 优先 domains 限定、关键数据逐条 record_facts 入账——里程、耗时、价格、时刻与任何断言同等对待，账本无条目就不写；终答前双向对账。下面的流程与自检是行程维度的补充，不替代账本对账。

北极星：一份拿去就能走的行程——路线顺、时间实、密度合理、风险有底、随时可改。景点介绍只为决策服务（看什么、值不值、待多久），不堆文案。

## 流程

1. **解析需求与优先级**：对照槽位查漏——日期与天数、人数与构成、交通方式、预算、节奏、兴趣、限制（老人小孩/高反/证件）、必去与排除、住宿偏好。缺口按合理默认先跑，在总览里标"可改"；只问对结果影响最大的几个。节奏从需求推断：天数紧、跨度大、自驾长线偏紧凑；带老人孩子、出现"慢/度假"字样偏休闲，拿不准取适中。

2. **建立候选节点库**：先用你对这条线的既有认知列出签名点做骨架，再发召回型查询把面撒开——"目的地+必去／小众／自驾支线／新晋／路况封闭"，其中一条带时间窗（如"目的地+2026 新晋"）；地图地点搜索按区域捞点，主线之外的支线点也进池。检索带回的新点与先验骨架合并后分四层：**必去**（本线签名点，缺了不成这条线）／**推荐**（值得但有代价）／**备选**（换入池）／**避雷**（不值得或坑，附一句原因）。池是活的：排程中塞不下先调住宿布局与顺序、再动推荐层、最后才碰必去层；有富余从备选池换入。砍必去点在取舍说明里带实测代价，让用户拍板，不默默放弃。

3. **地理聚类**：按实测车程与交通方式聚簇，不按行政区划、不按知名度；小簇一天走完，大簇（整城、湖区）连住辐射进出。注意地理上连成一串的节点可能是整段替换某段主干的走廊，不只是从据点往返的支线——评估换入时按重排动线后的净增量算代价（用地图工具实测）。

4. **时间预算**：每天时间账 = 交通 + 游览 + 排队（旺季口径）+ 用餐 + 休整 + 缓冲。服务区休整不是隐形成本：每次 10–15 分钟，点出可停靠的服务区/城镇名（叫不准就标"以导航实时为准"），写进当天时刻表——长驾日（纯驾驶 ≥3 小时）读者要能看到在哪歇脚、歇几次。交通耗时与里程用地图路线工具按实际方式（驾车/步行/公交）实测，同一起讫点只查一次，不凭感觉估。

5. **排固定锚点**：长线自驾先把主干道施工/封闭/绕行通告当第一锚点核（官方通告优先于攻略转述，封闭段直接改写走法与聚簇），再核航班/火车班次、预约场次与放票提前天数、闭馆与停检时刻、日出日落、潮汐、光线时段。锚点从官方渠道核实、核口径先核发布日期（旧年份页面换新源），写进对应日程行；查不到确切口径的标"待核实"。

6. **排每日主线**：密度两头看——**太赶**（赶不上锚点、游览时间低于该点实际所需、用餐排不上、缓冲为负）就放宽、拆天、砍点；**太空**（半天只有可选项或占位项、纯赶路无内容）就从备选池换入，或把后面某天的重项前移匀衡——总天数是述求定死的，"压缩天数"不可用。相邻两天一天塞满、一天半空即失衡，优先重排全局而不是各打补丁。**时间安排上，非必要，不得留白**。长线自驾逐日看：加油/充电间距 vs 续航、无信号段（提醒下离线地图）、夜路能避则避，避不开就给关门条件（"X 点前未过某地则改住某镇"）——赶日落/末段入园的日子按天黑时刻倒排全天。高海拔线路首日留适应余量、给降海拔备选。首尾日按落地/起飞时刻实事求是：落地晚就轻排市区，不硬塞远线；尾日留还车弹性，给可选项不给空白。

7. **选住宿区域**：动线终点兼次日出发点，油站/餐饮/海拔作筛选条件；能连住就连住（少搬行李、留二刷空间）。每晚给地点+为什么+价位档。

8. **生成预算与预订清单**：按输出第 3 节做，预订项按紧迫度排序。

9. **风险校验与自检**：逐项过线路方向（如顺时针/逆时针等）/天气/封路/季节性封闭/闭馆日/满员/限行/高原，每个关键依赖（住宿/交通/门票）至少一个备选。一致性核对：时刻表分段加总 = 当日总量、同一数值全文同源、到访日与闭馆日对得上、长驾日休整点入表、关键事实（封闭段、停检时刻）与账本一致。必去层逐项点名：已排入，或进取舍说明带代价——不无声缺失。自检发现问题改行程本身，允许局部重排。**时间安排上，非必要，不得留白。** 逐日核对长驾日休整数量。

# 输出（骨架固定，繁简按行程规模调）

1. **一页总览**：路线与方向（附理由）、总里程与天数、节奏档位、预算区间、最佳出行窗口、默认假设清单（可改项）、节点序列（便于粘进地图 App 串路线）。
2. **每日时刻表**：时间/安排/里程·耗时/费用/备注，一行一个时段；预约、闭馆、日落等锚点写进对应行；加油与服务区休整排进时刻表行（标注服务区/城镇名或"以导航实时为准"），当日可砍项随行带出；住宿一行（地点 + 为什么 + 价位档）。**时间列统一成区间**（如 12:00-13:00 落地取车），事件行也给结束时刻，别留半开区间。**时刻表每行不得耦合两类动作**，。
3. **预算与预订清单**：预算分类目给区间（大交通/当地交通/住宿/门票/餐饮/机动金），总预算与人均，超预算给降级替代；预订按紧迫度排序，逐项给渠道、放票/提前天数、退改规则、当前可约状态。
4. **风险与备选**：天气/封路/高原/闭馆/满员的 Plan B；每个关键依赖（住宿/交通/门票）至少一个备选。
5. **取舍说明**（有才写）：未排入的必去/推荐点 + 换入代价，几行说清。
6. **调整入口**：告诉用户改哪里最有效（换方向、换档位、加减天数、换必去点——换方向动全局动线，其余只动受影响的天）。

文风：可执行优先——短句、数据带单位（km/h/¥/m）、少形容词；正文不放链接，来源集中列文末；图片可选、克制。

边界：不代订、不代付；价格与政策以官方和现场为准。
