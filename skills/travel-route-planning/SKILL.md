# 旅游路线规划（贪心 + 装箱 + 拆分）

严格按以下步骤顺序执行；每一步产出的关键数据（坐标、里程、时长、排序与取舍结论、价格与政策要点）立即 record_facts 入账。

## 第一步：锁定参数，校验纯赶路可行性

1. 从用户输入锁定出发地、目的地、必去景点清单、总天数 N；用户未说明天数时，用 route_query(driving) 查询「出发地 → 目的地」直达里程与时长，按每日驾驶 ≤ 4.5 小时估一个合理天数。用户明示的单日驾驶上限、出发时刻等偏好，以其值覆盖默认约束，全程沿用。
2. 用 current_time 确认当前日期与出行窗口，判断是否节假日、旺季、特殊季节（汛期/封山期）。
3. 纯赶路校验：不含任何游览，仅把「出发地 → 目的地」直达路线按天切开（需中途过夜则估中途城镇），用 run_code 核算是否满足——总驾驶 ≤ 4.5 × N 小时；每天驾驶 ≤ 4.5 小时且能拆成 ≤ 2 小时的连续段。
4. 任一条不满足即整体不可行：向用户说明缺口（差多少小时 / 至少需几天），给出加天数、改目的地或缩小范围的建议后终止，不进入装箱；结论 record_facts 入账。

## 第二步：候选景点排序定位

5. 沿合理线路走向列出候选景点与途经城镇县。排序：用户点名的必去景点一律最高；其余按代表性、重要性由高到低，核心景区在前、顺路补充点在后。
6. 用 search_place 逐一定位排序后的候选景点，取得名称与「经度,纬度」坐标，record_facts 入账。

## 第三步：贪心装箱：逐个加入景点，每轮重算全程

装箱模型：N 个天 = N 个箱子，每箱驾驶容量 4.5 小时，全程容量 4.5 × N 小时（3 天即 13.5 小时）；每箱时间窗按约 8:00–21:00 估。从骨架行程「出发地 → 过夜点 → … → 目的地」起步，每轮只尝试加入一个景点：

7. 取候选清单中未尝试过的最高优先级景点，按绕行增量最小选插入位置。
8. 加入后重新规划受影响日程：
   - 用 route_query(driving) 重查受影响驾驶段的里程、时长与路线走向；已加入景点间顺序明显绕路时，先调序再查；
   - 重排休息点：按「单次连续驾驶 ≤ 2 小时、每 2 小时驾驶配 0.5 小时休息」的节拍，用 search_nearby 在长驾驶段中途检索高速服务区、加油站、城镇餐馆作为休息点，不堆砌；
   - 重排住宿：优先景点所在城镇或顺路县城，用 search_place 定位；
   - 核对时间窗：到景点时刻须落在其开放时段内、闭园前留足游览时长（大型景区 3–4 小时，小型 1–2 小时）。开放时间先按常识估（多数景区约 8:00–17:00，博物馆多周一闭馆），存疑的记入待核实清单，第四步检索核实。
9. 用 run_code 对新行程逐日核算「约束校验标准（旅游路线规划）」的两项硬约束：
   - 全部通过：保留该景点，record_facts 记录当前行程版本（景点集合、逐日安排、逐日驾驶时长）；
   - 任一不通过：按序修复后复校——① 拆分路段：把长驾驶段的住宿点改到中途城镇，或插入服务区休息点拆短连续驾驶；② 调整景点顺序：减少绕行；③ 更换路线走向：改走备选公路或环线。修复不增加天数、不删除已保留景点；
   - 修复后仍不通过：非必去景点则舍弃本轮景点，行程回退上一版本，record_facts 记录舍弃原因（当日超时 / 驾驶超限 / 开放时间冲突 / 绕行过远）；必去景点则不直接舍弃，生成备选方案（A：总天数 +1 后重排重校；B：换出等值低优先级景点腾出额度），record_facts 记录后在最终报告呈现供用户选择。
10. 回到第 7 条取下一个未尝试的景点，直到候选清单尝试完毕；已舍弃的景点不再重试。

## 第四步：搜索整合与交叉验证

11. 需要外部信息的用 web_search 检索，查到的价格、政策、天气要点 record_facts 入账；与行程无关的略过，查不到可靠来源的按常识估算并标注：
    - 各段里程、驾驶时长、路线走向：以 route_query 结果为主，关键段用 web_search 查其他地图源交叉验证；多源偏差 > 20% 时取保守值（更长时间），并在报告中标注两源数据；
    - 高速服务区、加油站、休息点：用 search_nearby 沿线复核，确定加油时机与休息点落位；
    - 景点开放时间、门票、预约规则：官网或官方公众号优先，含第 8 条记下的待核实清单；
    - 沿线各地（出发地、途经地、目的地）食宿与特色美食：每晚住宿区域建议 + 三餐落点；
    - 费用估算：油费（实际总里程 × 油耗 × 油价）、过路费（高速里程按约 0.5 元/公里估）、门票与住宿。
12. 检索结果若动摇行程可行性（重点景区闭园整修、预约不上），把受影响景点按第 9 条的舍弃流程处理，重排受影响日程。

# 约束校验标准（旅游路线规划）

第三步每轮加入景点后，用 run_code 逐日核算以下两项硬约束。

## 1. 驾驶额度

- 每日总驾驶 ≤ 4.5 小时；全程总驾驶 ≤ 4.5 × N 小时（3 天行程即 ≤ 13.5 小时）。
- 单次连续驾驶 ≤ 2 小时；超长段必须由服务区或城镇休息点拆开。
- 每 2 小时驾驶安排 0.5 小时休息：休息不计入驾驶时长，但计入当日时间预算。

## 2. 时间窗

- 逐日时间预算 = 驾驶时长 + 游览时长 + 0.5 小时休息节拍 + 用餐，总量须落在当日可用时间窗（约 8:00–21:00）内；预计 21:00 后抵达住宿点即不通过。
- 到景点时刻须落在开放时段内，闭园前留足游览时长。
- 每天至少预留 1 小时缓冲；节假日或单日 ≥ 3 个点时不得低于 1.5 小时。不允许靠压缩缓冲时间硬塞行程。

# 输出要求

最终报告按以下顺序输出；除「补充说明」可省略外，各节必备，不输出本清单以外的内容：

1. **概述**：线路走向、天数、总里程、总驾驶时长、纳入与舍弃景点数、各晚住宿城镇。
2. **取舍说明**：解释为何这样取舍——逐条列出被舍弃/换出的景点及原因（取自 record_facts 记录）；必去景点冲突时并排给出备选方案 A/B 供选择。
3. **全程驾驶分段**：表格（列：路段、里程、参考驾驶时长、路况/说明），覆盖全部驾驶段；交叉验证有偏差的段在说明中标注两源数据。
4. **每日行程**：每天先一句「今日主线」，再接表格（列：时间、安排、交通/修整、费用/预约）；驾驶段与 0.5 小时休息节拍须在表中体现。
5. **加油与服务区**：推荐加油点与时机、各服务区休息安排。
6. **每日食宿**：每晚住宿城镇与区域建议、三餐落点与当地特色美食。
7. **预约与出发前复查**：需预约/购票事项、出发前复查项（开放时间、天气、路况），每条附来源链接。
8. **旅游贴士**：错峰游览、加油时机等常识即可，不必检索。
9. **风险提示**：天气与路况（山区/夜间/季节性封路）、节假日拥堵、景区闭园或限流、疲劳驾驶风险。
10. **补充说明**（非必需）：假设与估算口径（总天数估法、费用估算、待核实而未核实项等）。
