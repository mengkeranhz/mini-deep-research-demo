# 旅游路线规划

严格按以下三步顺序执行；每一步产出的关键数据（坐标、距离、时长、结论）立即 record_facts 入账。

## 第一步：确定路线骨架（出发地 + 必去景区 + 住宿 + 目的地）

1. 从述求提取四类骨架要素：出发地、必去景区（全部，一个不能漏）、住宿点（每天过夜处）、最终目的地；
   用户未说清的（如住宿城市、行程天数、返程与否）按常识做合理假设，并在最终答案中说明。
2. 用 search_place 逐一定位上述地点，取得名称与「经度,纬度」坐标。
3. 用 route_query(driving) 查询骨架上相邻两点的距离与时长，按天排出顺路的骨架行程；
   多个景区的先后顺序若明显绕路，先调整顺序再查询。

## 第二步：填充细节（补充景点、服务区、加油站、餐馆）

4. 用 search_nearby 在骨架节点与长驾驶段的中途点周边检索：补充景点、服务区、加油站、餐馆等点位；
   按行程需要取舍（如每 2 小时左右驾驶段配一个服务区/加油站，景区附近配就餐点），不堆砌。
5. 每个候选补充点用 route_query 评估接入成本（绕行距离与时间），值得加入的写入对应日程。

## 第三步：约束校验（任一不通过 → 调整行程 → 复查受影响路段，直到全部通过）

6. 三项约束的硬性上限：绕路总增幅 ≤ 20%、每日缓冲 ≥ 1 小时、单日驾驶 ≤ 4 小时且单段连续驾驶 ≤ 2 小时；
   判定方法、计算口径与不通过时的调整策略见 reference/constraint-checks.md（用 read_file 按需读取）。
7. 逐日里程与时长核算优先用脚本：read_file 读取 scripts/route_check.py（含输入格式说明），
   把行程数据整理成其输入 JSON，用 run_code 执行得到逐项校验结论。
8. 任一校验不通过：按 reference/constraint-checks.md 的调整策略修改行程，用 route_query 复查受影响路段后重新校验。

## 输出要求

- 行程按天呈现：每日的驾驶段（起终点、里程、时长）、游览点、用餐/加油/休息安排、住宿。
- 附约束校验结论：总里程与骨架对比、逐日驾驶时长与缓冲时间，逐项说明通过或调整情况。
