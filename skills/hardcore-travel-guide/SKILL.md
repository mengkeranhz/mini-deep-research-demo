# 硬核自用旅行攻略

按本文件流程顺序执行。四条执行纪律贯穿全程：

1. **实时信息必须核实**：限速、票价、开放时间、预约政策、班次、补给点营业时间、汇率等时效信息，先查证再写入；海拔/坐标等静态地理数值以 search_place/route_query 返回为准，不另开 web_search 核实；禁止凭模型记忆输出确定性数值；查不到就按未核实处理——账本记 proxy/not_found，报告直接给区间与自查指引，不贴标签（见「工具与数据契约」）。
2. **路况与补给素材必须检索**：限速/横风/暗冰/落石路段、无信号区间、加油站/充电桩位置与营业时间、救援与医院等执行素材，必须来自第三步圈定对象集后的攻略深挖（官方/UGC 双管线，见执行流程）；禁止用模型记忆冒充实测路况或补给信息；查不到的素材账本记 not_found、报告不硬凑，常识性兜底作平实提示。
3. **关键数据立即入账**：坐标、里程/耗时、限速、海拔、价格、政策、班次、补给点、结论、路况要点，查到即调用 record_facts 写入事实账本（见「事实账本」）。不入账的数据等于没查到。
4. **假设与思考过程不进报告**：所有推测性内容记入事实账本（note 标「假设」与依据）；最终报告**不出现假设声明，也不出现 LLM 的思考过程**——不设「假设与待确认」清单、不写「假设」标注，也不写「查了 XX 来源/多方核实/权衡后选了 X/经 run_code 计算」这类检索、权衡、计算工具的元信息；影响出行的推测改写为可执行提示（关门时间、备选加油/住宿点、Plan B），只给结论与动作、不给推导；**例外（取舍单行）**：路线方向、签名点取舍、夜宿布局这类方案级决策，在总览或对应日给一行结论式理由（≤40 字，如「未含水上雅丹：D4 关门 14:00，往返 +4h 超当日里程上限」）——理由是结论的一部分，不算推导。

## 工具与数据契约

| 用途 | 工具 | 用法 |
|---|---|---|
| 当前日期/时区 | current_time | 报告时效标注以此为准，不用记忆里的「今天」 |
| 地点定位/坐标 | search_place | 逐个垭口、补给点、住宿城镇、景点取坐标；返回的 photos（标题+URL）记作图源（景点/美食配图用） |
| 交通耗时与里程 | route_query | 按实际交通方式（driving/walking/bicycling/transit）逐段实测，禁止凭感觉估耗时 |
| 周边设施 | search_nearby | 查住宿周边加油站、充电桩、医院、修理厂等；每晚住宿城镇调用 ≤1 次、一次查全多类设施 |
| 权威信源域名定位 | locate_sources | **时效数值类**核实的首次 web_search 前调用，定位官方域名清单（≤5 个：交通厅、公路局、景区官网、气象、12306/航司等）；产出供 web_search 传 domains 限定。路况/补给深挖（第三步圈定对象集后）不用本工具 |
| 限速/票价/政策/班次 | web_search + fetch_url | 走官方管线；web_search 传 domains 限定官方域名 |
| 路况/补给/风险实测经验 | web_search | **不带 domains**，走 UGC 管线（自驾论坛、路书平台）；仅对第三步圈定的入选路段/对象检索「路段名 + 路况/限速/加油/充电/救援」；景点/美食配图时传 `include-images: true`（响应末尾附带相关图片，随检索顺带取图） |
| 预算汇总/油耗/续航换算 | run_code | 显式计算，不口算 |
| 事实入账 | record_facts | **查到即调，不攒批**。入参 `facts` 数组，每条必填 dimension、period、status（found/proxy/not_found），可选 metric/value/source/note；同 dimension+period+metric 重复入账覆盖旧值（多条实测经验并存时各用独立 dimension）。返回「已入账 N 条（新增/覆盖更新/无变化）」+ 覆盖缺口提示；**无变化=数据已在账本，勿重复检索**；被拒条目按回执修正后立即重发。字段填写约定见「事实账本」 |

**信源双管线**——先分清查的是哪类信息，再选管线：

- **时效数值类**（限速、票价、开放时间、政策、班次、营业时间）：官方信源优先——交通厅/公路局、景区/场馆官网、政府文旅部门、12306/航司/高德等官方平台 ＞ 官方公众号/小程序 ＞ 权威媒体 ＞ 自驾论坛/路书平台（第三方实测仅作旁证）。web_search 带 domains 限定官方域名。
- **实测经验类**（路况、横风/暗冰路段、无信号区间、加油站/充电桩稳定性、救援口碑）：自驾论坛/UGC 是主信源——官方渠道只有道路公告口径，查不出「这条垭口晚上有大车、这段没信号」的真实路况。汽车之家自驾游论坛、越野 e 族、两步路/六只脚路书、走吧网、高德路书均为合法信源；web_search **不带 domains**，来源链接入账并标「UGC」。
- **决策级先验**（哪条走法经典、哪个对象是本线签名点、顺/逆时针利弊、经典夜宿序列）：允许先以模型经验提名，但**必须经 1 次不带 domains 的 UGC 检索证实/证伪后才可入账**——证实入账（source 标 UGC），证伪即弃；数值类先验仍按纪律 1 一律禁止。

**检索预算主次**：路况与补给是路书可执行性的根基——按**素材覆盖**分配检索，不按搜索次数对比：路况/补给/风险素材与景点/美食体验素材在账本的覆盖（条目数与细节量）不得薄于时效数值类。时效数值类靠 locate_sources + domains 精准命中、一次查清（已入账的限速/票价/开放时间不再检索），省出的检索投给深挖素材缺口；客观数据查得全、路况补给一笔带过属执行偏差，发现即纠正。素材覆盖对等是深挖阶段的分配准则，不是事后补齐指标——深挖收口时按「检索去重与止损」降级即算达标，不回头补检索拉平条数。

**检索去重与止损**（对付中后程重复核对与同义重查）：

- **语义去重**：同一对象同一 facet 已入账（含 not_found/proxy）即终态——不再用同义或变体关键词检索该 facet；仅当用户提供新线索或账本出现冲突时重查 1 次。
- **补检索封顶**：每对象每 facet 换词补检索 ≤2 轮，到顶仍不足即降级入账收口，不为凑素材条数继续换词。
- **阶段切换**：第六步起进入写作与校验阶段，**默认零新检索**——仅两类例外：门禁校验发现硬冲突（封路/停业/闭馆日错误）、账本完全空白的当日必填字段；其余缺口复用账本或标「约」给区间。
- **低风险细节不复核**：餐饮人均、备选店铺、小额停车费等单源即用；二次核对只针对影响动线、关门时间或总预算 >10% 的数值。
- **工具不重调**：同一起讫对的 route_query 实测值、同一城镇的 search_nearby 结果以账本为准复用；门禁重排只重排时刻与动线，不为重排追加检索。

**核实规则**：
- 每条价格/政策/限速核实时记录日期入账（current_time 会话内取一次复用，不逐条调用）；报告按「官方来源」呈现——正文零编号零链接、不带核实日期与口径，官方链接统一进文末「官方来源」附录。
- **口径年份如实入账**：引用旧年份发行口径（年卡、惠民卡、票价方案等）时，period 写口径年份（如「2025 版」），不得标成核实时点冒充今日有效。
- 交叉验证仅限三类：沿途加油站间距、热门门票预约政策、跨境证件要求（各限两个独立来源）；其余条目单源即可。两源冲突按「更官方、更新、可访问原文」一次取舍即定、记入账本 note，不追加第三方来源对账。
- **检索失败处理**：依次换关键词 → web_search 带 domains 限定官方域名 → fetch_url 直抓官网；仍失败则该条以 not_found 或 proxy 入账，报告中直接给区间估计与自查指引，不写核查过程。不得静默略过，不得编造。
- **否定性结论也是结论**：查实「已封路/加油站已拆/无需预约」立即入账，不反复检索同一问题。

## 事实账本

用 record_facts 维护本次路书的事实账本，作为最终报告的结算依据。字段约定：

| 字段 | 硬核路书场景填写 |
|---|---|
| dimension | 条目名，如「G318-折多山段-限速」「新都桥-加油点」「折多山-垭口海拔」「稻城亚丁-门票预约」「理塘-住宿海拔」 |
| period | 核实日期（YYYY-MM-DD）或政策适用期（如 2026-10-01~10-07） |
| metric | 口径限定，如「旺季」「小型车」「含早餐」；单一口径可留空 |
| value | 数值或结论，含单位（km、h、m、¥、km/h） |
| source | 来源链接或来源名，官网 URL 优先 |
| status | found=有来源核实；proxy=官方值缺失但可折算/旁证（note 写方法）；not_found=查实检索不到（note 写已尝试关键词与渠道） |
| note | 冲突取舍、有效期、适用条件、UGC 评价时点 |

**入账标签对齐**：`analyze_query` 声明的覆盖目标（`required_facts` 里的 dimension/period），入账时**逐字照抄**这两个标签，不自创变体——政策适用期、口径年份按目标声明原样写。覆盖度提示报缺口而该数据明明已查到，是标签错位：照抄目标字符串重新入账，不必重新检索。

**实测经验条目——按原话/细节级入账**：路况/补给/风险、景点/美食体验素材逐条入账；value 保留具体细节（路段桩号、时点、量级、口碑原话，如「折多山垭口晚 8 点后大车多、弯道暗冰」「早上去人少、雪峰顺光」），**禁止压缩成「路况差」「好吃」这类干巴结论**。每条素材各自命名 dimension（同 dimension+period+metric 会覆盖旧值）；source 填 UGC 链接，note 标「UGC」+ 评价大致时点。素材数量参考：每个入选路段/关键对象 ≥3 条、每日关键路段 ≥5 条即算充分（**账本已入账条目直接计入，不要求由新检索产生**）；不足时先复用账本、再对缺口补检索（每对象每 facet ≤2 轮，见「检索去重与止损」），仍不足即降级收口——降级状态入账本，报告平实呈现，不为凑条数继续换词。

**引用规则**：报告中的限速、里程、海拔、价格、政策陈述必须与账本一致，来源按「官方来源」处理——官方链接进文末「官方来源」附录，UGC 来源只入账本、不进报告；「已核实」仅指 status=found 的条目，proxy/not_found 一律如实标注。

## 执行流程

### 第一步：解析需求与优先级

**必须问清**（以下任一项缺失且无法从对话推断时，先集中一轮向用户提问，得到答复后再开始规划）：
- 出发地、目的地、出行日期与天数
- 人数与构成（是否有老人/儿童/孕妇/行动不便者）
- 车辆类型与续航（自驾：轿车/SUV/电车/房车，油箱或电池安全续航里程；徒步/骑行：单日里程上限）
- 总预算或人均预算区间
- 主交通方式（自驾/徒步/骑行/混合）
- 高海拔行程：海拔耐受与高原经验；出境游：证件与签证状态
- 徒步/骑行：单日体力与负重水平、累计爬升耐受（涉及徒步/骑行时）

**偏好槽位（不阻塞、不追加提问轮）**：对话中已提及的直接采纳；缺省按默认假设入账本（note 标「假设」）——
- 必去/排除清单：默认必去 = 第二步候选节点库必去层；
- 节奏档位（特种兵/适中/休闲）：默认适中，单日核心对象 2—4 个；
- D1 是否集合日：默认非集合日；高海拔线路首晚不安排全线最高海拔住宿；
- 兴趣权重（地貌/人文/摄影/美食/亲子）：默认均衡。

**优先级序**（后续任何取舍冲突按此裁决）：用户显式必去/排除 ＞ 硬约束（时间/安全/补给/海拔/证件）＞ 候选库必去层 ＞ 推荐层 ＞ 备选层。

**日期属性核实**（出行日期确定后立即执行）：web_search 当年国务院放假安排，逐日判定「普通周末」还是「法定节假日/调休日」并入账——两套口径下景区限额、限流、节假日限行规则不同，后续核实与排程按实际属性走。

**可假设**（不阻塞规划，但必须记入账本 note 标「假设」；报告不出现任何假设声明）：单日里程上限（默认 驾车铺装路 ≤400km、山路 ≤250km；徒步 健康成人 ≤25km/累计爬升 ≤1500m）、住宿档次（默认舒适型）、驾驶者数量与轮换、季节窗口。

### 第二步：建立候选节点库

- **经典动线对照（本步必做，2—3 次不带 domains 的 UGC 检索）**：查「路线名 + 必去/天花板/避雷」「路线名 + 行程/路书」「路线名 + 值不值得」，产出**候选节点库**逐条入账，四层定义——**必去**（本线签名点，缺了就不成这条线，主线门禁保护对象）；**推荐**（值得但有代价：绕路/加天/挤占他点，落选须记取舍与换入代价）；**备选**（时间富余或兴趣匹配时换入）；**避雷**（明确不值得或坑，含原因）。成熟线路同时记下经典走法骨架（里程量级、常规夜宿序列、常规天数），供第三步聚类与第六步核销取舍。此库只入账本，不进报告。
- 罗列途经路段、垭口、补给点、住宿城镇、候选景点；逐个 search_place 定位，坐标与海拔/城区关系入账。
- 调研路线背景前，先调用 locate_sources 定位官方信源域名（交通厅、公路局、景区官网、气象等），之后**时效数值类** web_search 优先带 domains 限定到这些域名；路况/补给深挖（第三步圈定对象集后）不带 domains。
- 调研路线背景：路况与限速、气候与季节窗口、高海拔与高反、边境/证件、救援与网络覆盖、当地油价/电价等；实时/官方信源优先，按「工具与数据契约」核实入账。

### 第三步：地理聚类（零检索初筛 + 圈定入选对象集）

本步不执行任何 web_search（路线级选点检索已在第二步「经典动线对照」完成，直接复用候选节点库），并把「谁值得花检索」一次圈死。

- **按天分段聚类**：同一天安排同一走向，减少折返与回头路；补给间距、海拔梯度相近的路段归为同一天；区域半径以「单日里程上限内可达」为界。
- **排序**：依据代表性、候选节点库分层（必去层优先）、车辆续航与驾驶强度偏好。
- **产出各段清单**：每段取前 2—3 个关键对象（垭口/补给点/住宿城镇/景点）标「深挖候选」，其余进**顺位递补池**。
- **圈定入选对象集**（此后所有深挖只对这个集合执行）：入选 = 各段「深挖候选」+ 必去层对象（未在候选内时补入）+ 每晚住宿城镇头部餐厅/住宿 1—2 家；递补池对象一律不深挖——不投入任何 web_search/fetch_url 素材检索；route_query 属测算工具、不算检索，仅第六步「推荐层落选披露」测换入绕段时可用（单次、入账）。
- **深挖规范（第四至八步共用的检索执行口径）**：
  - **先复用后检索**：发起检索前先对照账本——已入账且无冲突的 facet（门票/预约/开放时间、玩法/亮点、口碑/避坑、图源、限速/路况、补给、风险/海拔）直接复用，禁止重查；只为空缺或冲突未解的 facet 检索，一次查清。参照检索词：路段「路段名 + 限速/路况」「城镇名 + 加油站/充电桩/补给」「路段名/垭口 + 风险/海拔/救援」；景点「景点名 + 预约/门票/开放时间」「景点名 + 玩法/亮点/评价」；餐厅「店名 + 特色菜/必点/口碑」。
  - **双管线**：官方数值类（门票/预约/开放时间/班次/限速）走 domains；实测经验类（路况/横风/暗冰/无信号/加油充电/风险/口碑）不带 domains；景点/美食 UGC 检索传 `include-images: true` 随检索顺带取图。
  - **粒度到执行要素**：具体限速值、桩号区间、营业时间、救援电话——能直接进时刻表与附录，不是概括性介绍。
  - **命中就深读**：素材丰富的路书/攻略帖/官方公告挑 1—2 条 fetch_url 取全文。
  - **补检索封顶**：每对象每 facet 换词 ≤2 轮，到顶按降级收口（not_found/proxy 入账）；**禁止编造限速值、加油站、救援电话**。
  - **细节级入账**：素材逐条独立 dimension（每入选对象 ≥3 条、每日关键路段 ≥5 条为充分线），口碑保留原话口吻，source 标 UGC 与时点。
  - **顺位递补**：深挖发现入选对象硬伤（封路、补给点停业、口岸/景区关闭）时，从递补池按顺位换入并对递补对象执行同规格检索，受影响当日重走第六步。

### 第四步：时间预算

- **交通**：聚类各段用 route_query 按实际交通方式逐段实测；同一起讫对只测一次，已入账即复用。**拆分段口径**：只返回整段值时按时间片段拆分，备注整段口径，拆分加总必须等于整段值，不自创里程/耗时。
- **逐项显式加总**：交通（实测）+ 游览停留 + 排队（旺季口径，取账本素材）+ 用餐 + 休整——驾驶日连续 ≤4h、单日总驾驶 ≤6h、服务区休整 ≥20min；徒步日连续 ≤2h 一个休息/补水点——最后加**缓冲 ≥20%**，核对放得下当日活动窗口；塞不下先砍弹性对象，缓冲最后动。
- 停留时长/排队/路况素材缺口，按第三步深挖规范补检索，不为估算拍脑袋。

### 第五步：排固定项（锚点先行）

- **锚点清单**：航班/火车班次、预约场次、停检/停止入园/闭馆时刻、开放时间与闭馆日、放票节点、日落日出与光线窗口（盐湖镜面/丹霞/沙漠日落/垭口顺光）、潮汐/赶海窗口（涉海线路）——全部官方管线核实入账。
- **先锚定不可移项，再填弹性项**：锚点时刻先固定，游览、用餐、休整、加油等弹性项填进锚间空档；锚点冲突时保锚砍弹（砍项记「可砍项」）。
- 预约类锚点同步产「预订」子项素材：渠道、放票时间、提前天数（如莫高窟 A 类票提前 30 天）、退改规则——供「预算与预订清单」汇总。
- 高海拔日在首个锚点前留适应缓冲；光线敏感对象必须落在对应时段，与时刻表备注口径一致。

### 第六步：排每日主线（主线门禁）

- 每天 **2—4 个核心点**，锚间填弹性项；逐日时刻表一行一个时间片段（见「输出要求·每日时刻表」），里程/耗时用账本 route_query 实测值逐段加总。
- 逐日标**关门时间**：基于账本核实的营业时间/里程/补给反推（如「16:00 未过某垭口则改住某镇——垭口后 80km 无补给」），不得拍脑袋；每个 ≥300km 或穿越无补给/无信号段的日子必有关门时间。
- **主线门禁（自动校验，不询问用户）**，两道核销：
  - **必去层核销**：每个必去对象须满足其一：①已排入某日动线；②先做 1 轮重聚类尝试（调夜宿布局吸收，如基地镇改两晚、相邻日拆并），仍与硬约束冲突（天数/单日里程/季节封闭/用户明确排除）才允许排除，取舍记入账本（dimension 形如「主线-未含XX-取舍」，value 写原因与尝试结果）。
  - **推荐层落选披露**：未入选的推荐层对象逐条记「主线-未含XX-取舍」——落选原因（≤40 字）+ **换入代价**（Δkm/Δh/挤掉谁：主线段复用账本实测值拼算；主线外绕段允许 route_query 单次实测入账；不新开 web_search）；报告在每日时刻表后逐条列出「未含与换入」行（与关门时间同置表下、不进表格）——对象挂在聚类分段时所属的那一天；整段未排入主线的（如整个方向被裁），挂最接近的一日或总览一行——不让用户猜哪些点被放弃了。
- 每天标注 1 个**可砍项**（砍掉不影响主线），写入当日时刻表末行。

### 第七步：选住宿区域

- **选址原则**：住宿城镇落在当日动线终点、且位于次日主方向上（靠近次日出发点）——**配套与价格让位于方向**；本步只到「城镇级」粒度，不排具体时刻。
- **海拔梯度**：每日净升/降合理；高海拔线路首晚不安排全线最高海拔住宿；有高反史者住宿点不过夜高风险线。
- **补给验证**：search_nearby 每晚 ≤1 次、一次查全加油/充电/医院；任意两可用加油/充电点间距 ≤ 车辆安全续航的 70%；加油站不作唯一依赖，各配 1 个备选。
- **住宿冗余**：每晚给 1 个备选（尤其高反/赶路不确定的夜晚）。

### 预算与预订清单

- **只产清单与操作指引，不代订**；紧俏项值不值得抢，以深挖「是否值得/避雷」结论为准。
- **预算**：类别齐全、经 run_code 显式计算可复算（口径见「预算体系」）；总预算=Σ各类别、人均=÷人数；超预算 10% 给降级替代、超 20% 触发第八步重排。
- **预订**：城际大交通（建议车次/舱位、购票渠道、放票与候补规则）；各晚住宿（城镇、价位区间、取消政策）；紧俏门票与必须预约的餐厅（渠道、放票时间、提前天数、Plan B）；细化后补齐可退改项（具体场次门票、餐厅、体验、接送站），逐项标注可否免费取消及截止时间，落位对应对象的「预订」子项。
- 全部写「当前可约状态」（核实时点入账本），无「已订/已锁位」表述。

### 第八步：风险校验（质量门禁）

门禁对象是**路书**——行程本身可不可行。校验覆盖：闭馆、限行/封路、天气、签证/证件、高原、安全（疲劳驾驶/徒步强度/补给）。

**硬约束**——任一不过，按回退路径重排；最多重排 2 轮，仍不过则如实输出冲突点并给 A/B 两案：

| 校验项 | 判定阈值                                                                                                        | 不通过时回退到 |
|---|-----------------------------------------------------------------------------------------------------------------|---|
| 时间冲突 | 无任何时间重叠；预约时段前有充足交通余量                                                                        | 第六步当日重排 |
| 营业/开放匹配 | 到访时刻落在开放时间内且避开闭馆日                                                                              | 第六步换序或换日 |
| 疲劳驾驶 | 连续驾驶 ≤4h；单日总驾驶 ≤6h；长时间驾驶需服务区休整                                                            | 第六步拆段或第七步换住宿点 |
| 徒步强度 | 连续徒步 ≤2h 须有休息/补水点；单日徒步里程/爬升不超体力档位上限（健康成人约 25km/1500m）；天黑前有收尾/下撤方案 | 第六步砍段或拆天 |
| 补给间距 | 任意两可用加油/充电点间距 ≤ 车辆安全续航的 70%；无信号路段有补给预案                                            | 第七步换补给点或第六步拆段 |
| 海拔梯度 | 每日净升/降合理；有高反史者住宿点不过夜高风险线；高海拔首日留适应缓冲                                           | 第七步换住宿点或加适应日 |
| 总预算 | 估算总费用 ≤ 预算上限（未给预算则报区间）                                                                       | 第六步砍次级对象或降住宿档次 |
| 预订可得性 | 关键预订项沿用「预算与预订清单」入账的可约状态与时点核对，不重复检索（仅放票节点已过且该项决定当日去留时补查 1 次） | 第三步换替代项或第六步换日期 |
| 封路/限行/天气 | 途经路段无长期封闭施工/交通管制/季节性关闭；雨雪沙尘横风高发期有绕行或调序方案 | 第三步换线或第六步调序 |
| 证件/签证 | 证件有效期/签证状态/边防证与全程匹配（出境与边境段必查） | 第一步重询用户或换目的地 |

**预订可得性口径**：核实的是**可约状态**（渠道当前显示），**不是锁位**——本流程不代订、未下单，热门票在出行前随时可能售罄。因此每个紧俏预订项必须配 Plan B，并在「预订」子项提醒用户尽早下单、关注放票时间。

**软约束**——违反则保留方案，但必须在「风险预案」中显式说明：单日驾驶占总行程时间 >60%；人均日步行超过人群阈值（含徒步/景区日，按下表取最严档）；缓冲 <20%；单日核心点顶格（4 个）且无弹性空档；首尾日行程过满。

| 同行构成 | 人均日步行预警阈值 |
|---|---|
| 健康成人 | >15km |
| 含 12 岁以下儿童或 65 岁以上老人 | >8km，单段连续步行 >2km 需设休息点 |
| 含孕妇或行动不便者 | >6km，每日至少 1 个长休整点 |

**重排即重校**：主线排布或撰写中修改了任何时间点/动线/补给点，相关当日的硬约束校验重走一遍；时刻表里程/耗时以**账本已入账的 route_query 实测值**逐段加总为准，同一起讫对不重复调用 route_query（仅未实测过的新段才调）。

### 交付自检（Rubric）

自检对象是**路书**——路书与账本是否零冲突、披露是否闭环、口径有没有夸大、决策与冗余是否到位。任一不过**只改路书，不重排行程**；素材门禁不过则退回深挖补检索；若发现方案级错误退回第八步。

| # | 检查项 | 通过标准 |
|---|---|---|
| 1 | 价格可溯源 | 路书每条价格/限速/海拔在账本有同值条目；proxy/not_found 直接给区间与自查指引，不冒充核实 |
| 2 | 数值一致 | 双向核对：路书所有数值（里程/耗时/海拔/限速/预算）与账本零冲突；时刻表拆分段加总 = 账本整段口径；不一致以账本为准改路书，不为消解冲突重新检索（账本内两源冲突且影响动线时除外，限补 1 轮） |
| 3 | 无思考过程与假设 | 路书不出现「假设」标注，也不出现检索/权衡/计算工具标注等思考痕迹（「查到 XX」「权衡后」「经 run_code 计算」等）；推测已记入账本 note，影响出行的推测转为关门时间/Plan B；方案级取舍的单行理由属结论、不算思考痕迹（见执行纪律第 4 条例外） |
| 4 | 门禁留痕 | 第八步硬约束校验结果逐一记入账本（dimension 形如「门禁-补给间距」，value 写 通过/重排后通过）；路书不出现校验项打勾清单 |
| 5 | 软约束披露 | 无违反 → 风险预案不写软约束项；有违反 → 全部在风险预案说明并给缓解措施 |
| 6 | 预订口径 | 预订项均写「当前可约状态」（核实时点入账本），无「已订/已锁位」表述 |
| 7 | 预算可复算 | 总预算=Σ各类别；油费=总里程×油耗×油价、过路费=高速里程×费率经 run_code 计算，逐项可复算；估算项标「约」并给区间 |
| 8 | 风险与冗余 | 每个关键依赖（加油/充电/住宿/预约）有 1 个备选；每条风险有触发条件 + 处置动作 |
| 9 | 关门时间 | 每个 ≥300km 或穿越无补给/无信号段的日子有一条关门时间；关门时间含触发条件 + 动作 + 依据，依据来自账本核实值 |
| 10 | 篇幅与密度 | 每自然段 ≤80 字、景点/餐饮短项 ≤80 字、住宿短项 ≤50 字、关门时间单行 ≤40 字、附录一行一条；短项置于时刻表上方、预订与 tips 为两个子项；时刻表一行一个时间片段、末行可加「可砍项」，表后跟关门时间与「未含与换入」行；景点/美食每段 ≤1 张克制小图（可外链）、无图卡；无渲染性文字、无 emoji 堆砌 |
| 11 | 官方来源 | 「官方来源」附录只逐条列官方来源、无核实日期与口径；正文零编号零链接、不带核实日期；UGC 来源不进报告 |
| 12 | 签名点覆盖 | 第二步候选节点库「必去层」对象全部入选，或账本记有排除理由（含 1 轮重聚类尝试）；推荐层落选对象全部有取舍行与换入代价（对应日时刻表后「未含与换入」行）；未含签名点处在对应日给一行取舍理由 |
| 13 | 节奏与布局 | 每日核心对象 2—4 个、时间缓冲 ≥20%；各晚住宿位于次日主方向；首尾日不排满 |
| 14 | 光线锚点 | 光线敏感对象（盐湖镜面/丹霞/沙漠日落/垭口顺光）排在对应时段，与时刻表备注口径一致 |

## 预算体系

- **类别齐全**：城际大交通；当地交通（油费=实际总里程×油耗×油价、过路费、停车、打车、公交）；住宿；餐饮；门票；保险；签证/入境费用（出境）；税费/小费（境外）；购物与机动金（建议预留总预算 10%—15%）。
- **过路费是估算项**：route_query 不返回过路费。优先 web_search 核实途经路段费率并入账；查不到时按高速里程×0.5 元/km 估算——这是**经验估算**（实际约 0.4—0.6 元/km，地域差异大），估算方法记入账本 note，预算表提示以 ETC/导航实际费用为准。
- **优待票价**：儿童/老人/学生票在预算表「门票」行明细列单列，身高/年龄口径以账本核实值为准。
- **公式**：总预算=Σ各类别；人均=总预算÷人数。境外按核实时点汇率折算，来源与时点入账本。
- **超支预警**：总费用超预算 10% → 预警并对每个超支项给降级替代；超 20% → 触发硬约束重排。**预警落地为具体动作，不在路书输出「超预算预警」类字面标签**——触发阈值是内部计算口径，只驱动降级替代与重排。

## 风险与冗余预案

关门时间、备选与 Plan B 是硬核路书的骨架，**默认全量输出**（不是按需），每个关键节点都要有兜底：

- **关门时间**：每个关键节点给「触发条件 → 动作 → 依据」，依据来自账本核实值（里程/耗时/营业时间/补给间距反推）。
- **补给冗余**：沿途加油站/充电桩不作为唯一依赖，各配 1 个备选；无信号路段标注并给「提前下离线地图」提示。
- **住宿冗余**：每晚住宿给 1 个备选（尤其高反/赶路不确定的夜晚）。
- **预约满员**：候补/退票高峰捡漏时段、同区域替代。
- **恶劣天气/封路**（暴雨/沙尘/横风/落石）：绕行或调序，室内或就近替代。
- **航班取消/高铁晚点**：后段留缓冲、优先可退改票。
- **体力/高反不支**：每日标注 1 个「可砍项」，砍掉不影响当日主线；高反时降海拔住宿。

## 合规与责任边界

- 不代订、不代付、不代填任何订单；只产出清单与操作指引。
- 签证、疫苗、医疗、法律事项只提供官方信息渠道与常识性提示，不构成专业建议。
- 自驾/户外风险自担：路书提供的限速、路况、补给信息以现场交通与官方公告为准。
- 紧急情况以当地官方指引与紧急电话为准。
- 价格、政策、开放状态、路况最终以官方渠道与现场为准；**用户需自行复核**。

# 输出要求

## 风格基调

**核心原则：可执行、可验证、有冗余、有关门时间——像「飞行计划 + 施工图」，不是游记。**

路书是给自己和同行人落地用的，不取悦读者：**先给数据与决策，不抒情**；表格管执行，短句管决策，冗余管兜底。事实、价格、来源、核实状态一个字都不能松；形容词与渲染性文字一律删。

- **短句电报式**：写「D1 7:00 满油出发，折多山垭口 4298m，16:00 前未到新都桥则砍塔公草原」；不写「清晨的草原美得让人心醉」。
- **每自然段控制字数**：正文自然段 ≤80 字（约 2—3 行）；景点/餐饮短项 ≤80 字、住宿短项 ≤50 字；关门时间单行 ≤40 字；附录表单元格短语化（≤20 字/格）；全篇不出现超过 5 行的连续正文。**例外**：每日时刻表的「备注」单元格是执行细节主场，允许承载完整要点（可长），不套 ≤20 字。
- **数据带单位与口径**：里程 km、耗时 h、海拔 m、价格 ¥、限速 km/h，均带单位；估算类数值标「约」并给区间，不写死。
- **关门时间必须显式**：每个关键节点给「若 X 点未到 Y 则改 Z」式关门时间，关门时间基于账本核实的里程/耗时/营业时间反推，不拍脑袋。
- **冗余必须有**：关键依赖（加油/充电/住宿/预约）各给 1 个备选；不把唯一加油站/唯一住宿当唯一依赖。
- **克制排版**：至多在风险等级处用少量符号（⚠️/❗），正文不放装饰性 emoji；加粗只给决策词与关键数值，不刷屏。
- **不写思考过程与假设**：报告只给结论与动作，不写检索过程、权衡取舍、计算工具标注（「经 run_code 计算」）与「假设」类推导；这些只留在事实账本。拆分段口径、估算标「约」属执行数据，保留；方案级取舍的单行理由（见执行纪律第 4 条例外）同样保留。

## 官方来源

报告最末设「官方来源」附录，**只逐条列官方来源**（景区/场馆官网、交通厅/公路局、政府文旅部门、12306/航司/高德等官方平台），一条一行：

> 官方来源名 · URL

- **正文零编号零链接**：正文（总览/短项/时刻表/关门时间/各附录）不出现脚注编号（`[1]` 等）与任何链接；链接只在「官方来源」附录集中，一条一行。
- **不写核实日期、不写口径**：核实日期与口径只入事实账本，不进报告；正文数据也不带「2026-09 核实」式日期。
- **不列 UGC 来源**：路书/论坛等实测经验来源只入账本，不进「官方来源」附录；实测经验按平实提示写进正文，不标来源。
- **proxy/not_found 如实给区间与自查指引**：查不到的数据直接给区间与「以现场为准」提示，不在附录冒充官方核实。

## 图片（克制，可选）

景点与美食段落最多各配 1 张小图，克制、不喧宾夺主；**不生成图卡**（不调用 render_card），只用 Markdown `![](URL)` 外链引用。

- **取图**（同 travel-viral-guide）：① search_place 返回的 photos（标题+URL）直接复用；② 景点/美食的 web_search 传 `include-images: true`，响应末尾附带查询相关图片，随检索顺带取图，不为图片另花检索。
- **只用可外链开放图源**：unsplash / 高德 POI 图（store.is.autonavi.com）/ pixabay；高德图优先用 search_place photos 现成返回的。pngtree/alamy/shutterstock 等图库直链会被防盗链拦截、图会静默丢失。
- **尺寸克制**：宽度 ≤240px，`![](URL)` 一行，不加 HTML、不写图注（至多写对象名）。
- **来源入账不进报告**：图源与版权随图记入事实账本，图片旁不标「图源/仅参考」类备注。
- **拿不到就免**：两条渠道都拿不到合规可外链图，该对象无图，不硬凑。

## 路书内容（Markdown 文件，不带图卡）

输出为一个 Markdown 文件：用 run_code 把终稿写入根目录 `<主题>.md` 并告知用户文件路径。**不调用 render_card、不生成图卡**；景点/美食段落最多各配 1 张克制小图（见「图片」）。按需组织以下内容，篇幅主次：**每日对象短项（景点/餐饮/住宿）+ 每日时刻表是主体**，附录一行一条最精简，无渲染与铺垫文字。

### 总览（不加标题，正文第一块）

- 一句话说清：**起终点 → 途径**，总里程、建议天数、最佳月份窗口；顺时针/逆时针（或正走/反走）选择理由——一句讲清（海拔适应 / 车流方向 / 补给分布）。
- **海拔剖面摘要**：文字列关键高程点（起点 → 最高垭口 → 各住宿点，m），用单行序列或小表，不用图；有 GPX 时注明「导入可看剖面」。
- **轨迹与离线地图**：GPX/KML 获取渠道（两步路/六只脚等）、离线地图需下载覆盖的区域（州/市），一句讲清「哪些路段无信号、要提前下离线」。

### 每日对象短项（景点/餐饮/住宿，置于时刻表上方）

每天先列当日对象的短项，再放时刻表。**对象严格按当日动线时序排列**（早餐 → 景点 A → 午餐 → 景点 B → 晚餐 → 住宿，住宿收当日尾），不按类型分组；每个对象自成一段、**段首标题加粗单独一行**。短项是精炼要点，时刻表备注是展开的执行细节——同一事实两处口径一致、不重复堆砌，详细值只在最详细处写全。

- **景点**：每个景点自成一段（**≤80 字**），段首标题加粗单独一行（写对象名，如「**双桥沟**」），正文写「看/玩什么 + 停留时长 + 为什么值得」，可织入特色、玩法、亮点、近期评价与口碑等 UGC 细节（取账本实测经验条目、保留原话口吻、不编造），有温度但克制、不写机位与出片。段下两个子项各一行，有才设：`- **预订**：渠道 + 放票/提前天数 + 退改（≤50 字）`、`- **tips**：开放时间/穿衣/海拔/错峰等注意（≤50 字）`。**最多配 1 张克制小图**（见「图片」）。
- **餐饮**：早餐/午餐/晚餐各一段（**≤80 字**），段首标题加粗单独一行（写「早餐/午餐/晚餐 · 店名」，如「**午餐 · 卧龙镇**」），正文写「吃什么 + 特色菜/必点（一句为什么）+ 人均/排队」，可织入近期评价与口碑（取账本实测经验条目、保留原话口吻、不编造）；没调研到的如实写「到了再找，XX 一带吃的密集」，不编「必点」。**最多配 1 张克制小图**（见「图片」）。
- **住宿**：一段（**≤50 字**），段首标题加粗单独一行（写「住宿 · 城镇或酒店」，如「**住宿 · 四姑娘山镇**」），正文写「住哪 + 为什么（近加油站/海拔低/有制氧机）+ 海拔 + 供氧 + 备选」——原「住宿海拔表」的海拔/供氧/备选点直接写进本短项，不另设附录。
- 对象间交通衔接（景点↔餐厅↔住宿）一句话带过，织进相邻对象正文末尾，不单独成段、不配图。

### 每日时刻表（核心，细颗粒，一天一张）

每天一张表，**一行一个时间片段/活动**（不是一天一行）——把当日动线拆到「几点到几点、干什么、怎么挪、花多少钱」的可执行颗粒。列按需取舍（典型列，不硬套模板，以信息密度为先）：

| 时间 | 安排 | 里程/耗时 | 费用（2 人） | 备注 |

- **时间**：起止时点（如 07:00–10:10）；跨日到次日则注明日期。
- **安排**：地点 + 动作（早餐/加油/驾车/景区/用餐/入住）；驾车段写明道路与起讫点（如 G3011→G215）。
- **里程/耗时**：route_query 实测值，逐段加总 = 当日总量；**拆分段口径**——route_query 只返回整段值时，按时间片段拆分估算，并在备注注明整段口径与拆分加总（如「整段 210km/4h10m，拆①+②」，拆分加总必须等于整段，不自创数据）。
- **费用（2 人）**：该片段的支出（门票/餐饮/油费）；门票写单价×人数，优待票价口径在备注注明。
- **备注**：该片段的执行要点——限速、海拔、无信号、开放/停售时间、放票规则、检票规则、禁止事项、咨询电话、拆分段口径等；**备注是硬核信息的主场，允许承载完整执行细节（可长）**，其余单元格仍短语化。
- **预约并入短项/备注**：不单设「预约」列——预约要点（渠道/放票/退改）写在短项「预订」子项，本片段的预约执行细节（如提前 30 分钟抵达、刷身份证检票）写入备注，两处口径一致、不重复堆砌。
- **加油/充电并入本表**：不另设附录「加油/充电表」——加油/充电动作作为时刻表行（或写入驾车行备注），间距、营业时间、备用点写进该行备注。
- **休整/休息点**：长时间驾驶服务区休整行（≥20min，标注有无加油/卫生间）；徒步日每 ≤2h 一个休息/补水点行，标注补水点/营地/下撤点。
- 表末可加一行「**可砍项**」：砍掉不影响当日主线的对象/动作 + 砍掉省多少（时间/费用）+ 代价（体验降级）。
- 表后跟「**未含与换入**」行（有则列，与关门时间同置表下、不进表格）：当日动线/区域被裁掉的推荐层对象，一行一条——对象 + 落选原因（≤40 字）+ 换入代价（Δkm/Δh/挤掉谁）；当日无落选对象不设。
- 每张表后跟 1—2 行**关门时间**：本日不可越过的时点/位置 + 改道动作 + 依据（例：「16:00 未过折多山垭口，就地住康定——垭口夜间暗冰、大车多、无信号」）。驾驶日标注服务区休整点。

### 关门时间与冗余

不单独成章，并入每日时刻表后：每条关门时间一行，触发条件 + 动作 + 依据，「未含与换入」行同置其后；关键依赖（加油/充电/住宿/预约）各给 1 个备选，随时刻表「备注」或关门时间行带出。

### 附录（独立成节，表格/清单，一行一条）

- **装备清单**：按车辆/随车工具/个人/应急分类，一行一条。
- **风险预案**：高反、沙尘、横风、夜间禁行、动物横穿、景区关闭等，每条给触发条件 + 处置。
- **预算表**：油费、过路费、住宿、门票、餐饮、备用金，一行一类。
- **应急信息**：沿途医院、修理厂、救援电话、撤离点，一行一条。

### 官方来源（报告最末）

只逐条列官方来源（来源名 + URL），一条一行；不写核实日期、不写口径、不列 UGC 来源。
